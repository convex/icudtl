# icudtl

ICU 77 data (`icudtl.dat`) for V8, with current IANA time zone data. A drop-in
replacement for [`deno_core_icudata`](https://crates.io/crates/deno_core_icudata).

```toml
[dependencies]
icudtl = "0.77"
```

```rust
v8::icu::set_common_data_77(icudtl::ICU_DATA).unwrap();
```

`ICU_VERSION` and `TZDATA_VERSION` give the versions of the shipped data.

## Why

V8 reads time zone data from the ICU data the embedder gives it.
`deno_core_icudata` is only republished for new ICU major versions, so its
tzdata falls behind: ICU 77.1 has tzdata 2025b, which gets 2026's changes in
Canada and Cuba wrong. This crate keeps the ICU 77 data and only replaces its
four time zone resources (`zoneinfo64`, `metaZones`, `timezoneTypes`,
`windowsZones`) with
[Unicode's builds](https://github.com/unicode-org/icu-data/tree/main/tzdata/icunew)
for the latest tzdata release. Every other item stays byte-for-byte the same.

## Layout

- `base/icudt77l.dat`: the unmodified ICU 77.1 data (see [`base/README.md`](base/README.md)).
- `tzdata/`: Unicode's resources for `TZDATA_VERSION`, from `icunew/<version>/44/le`.
- `src/icudtl.dat`: generated by `cargo xtask generate`. Only `src/` is published.
- `xtask/`: the generator and the data tests.

## Updating tzdata

```sh
scripts/update-tzdata.sh 2026g  # downloads, regenerates, bumps the patch version
cargo test
scripts/check-icupkg.sh         # optional; needs icupkg (icu-devtools)
```

## Versioning

`0.77.x` is ICU 77. The patch version is bumped on every data change.

- **Same ICU major** (e.g. an ICU 77.x patch release): replace
  `base/icudt77l.dat`, update `base/README.md` and `ICU_VERSION`, bump the
  patch version, and run `cargo xtask generate`.
- **New ICU major** (e.g. 78): consumers must upgrade V8 at the same time.
  Branch `icu-77` from `main` to keep updating ICU 77. Then on `main`, replace
  the base, update `BASE` in `xtask/src/lib.rs`, `ICU_VERSION`, and the
  `set_common_data_*` references, and set the version to `0.78.0`.
