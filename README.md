# icudtl

ICU 77 data (`icudtl.dat`) for V8, with current IANA time zone data. A drop-in
replacement for [`deno_core_icudata`](https://crates.io/crates/deno_core_icudata).

```toml
[dependencies]
icudtl = "0.77"
```

```rust
v8::icu::set_common_data_77(icudtl::ICU_DATA).unwrap();
```

`ICU_VERSION` and `TZDATA_VERSION` give the versions of the shipped data.

## Why

V8 reads time zone data from the ICU data the embedder gives it.
`deno_core_icudata` is only republished for new ICU major versions, so its
tzdata falls behind: its ICU 77.1 data has tzdata 2025b, which gets 2026's
changes in Canada and Cuba wrong. This crate keeps the ICU 77 data and only
replaces three time zone resources (`zoneinfo64`, `timezoneTypes`,
`windowsZones`) with
[Unicode's builds](https://github.com/unicode-org/icu-data/tree/main/tzdata/icunew)
for the latest tzdata release. Every other item stays byte-for-byte the same.

Unicode also publishes `metaZones`, but it comes from the latest CLDR and maps
zones to metazones that ICU 77's locale data may not name. For example, CLDR 48
moves `Pacific/Honolulu` to a new `Hawaii` metazone, so its long name would
become `GMT-10:00`. The crate keeps ICU 77's `metaZones`. The 2026 Canada
changes are encoded to work with the existing metazones.

## Layout

- `base/icudt77l.dat`: the unmodified ICU 77.1 data, byte-identical to
  `deno_core_icudata` 0.77.0 and Chromium's ICU at
  [`ee5f27adc`](https://chromium.googlesource.com/chromium/deps/icu/+/ee5f27adc).
- `tzdata/`: Unicode's resources for `TZDATA_VERSION`, from `icunew/<version>/44/le`
  (all except `metaZones.res`).
- `src/icudtl.dat`: generated by `cargo xtask generate`. Of these, only `src/`
  is published.
- `xtask/`: the generator and the data tests.
- `e2e/`: a test that loads the data into V8 (`cargo test -p e2e`; downloads V8).

## Updating tzdata

```sh
scripts/update-tzdata.sh 2026g  # downloads, regenerates, bumps the patch version
cargo test
scripts/check-icupkg.sh         # optional; needs icupkg (icu-devtools)
```

## Versioning

`0.77.x` is ICU 77. The patch version is bumped on every data change.

- **Same ICU major** (e.g. an ICU 77.x patch release): replace
  `base/icudt77l.dat` and its source note above, update `ICU_VERSION`, bump the
  patch version, and run `cargo xtask generate`.
- **New ICU major** (e.g. 78): consumers must upgrade V8 at the same time.
  Branch `icu-77` from `main` to keep updating ICU 77. Then on `main`, replace
  the base, update `BASE` in `xtask/src/lib.rs`, `ICU_VERSION`, and the
  `set_common_data_*` references, and set the version to `0.78.0`. If the new
  base has the same CLDR version as Unicode's latest `metaZones.res`, add it
  back to `TZ_RESOURCES`.

## Automation

- `update-tzdata.yml` (daily): when Unicode publishes a newer tzdata release,
  opens or updates a PR "Update tzdata to <version>" for each branch in its
  `matrix.branch` list. Add `icu-<major>` branches there.
- `check-icu-major.yml` (weekly): opens an issue when a newer ICU major is
  available.
- `release.yml`: publishes to crates.io when a `v<version>` tag is pushed. See
  [Releasing](#releasing).

Required configuration:

- A token for update PRs, so CI runs on them: either a GitHub App (variable
  `TZDATA_APP_CLIENT_ID`, secret `TZDATA_APP_PRIVATE_KEY`) or a fine-grained
  PAT (secret `TZDATA_UPDATE_TOKEN`), with read and write access to Contents
  and Pull requests. Without one, the workflow falls back to `GITHUB_TOKEN`.
  That needs "Allow GitHub Actions to create and approve pull requests"
  enabled, and CI won't run on those PRs.
- A [trusted publisher](https://crates.io/docs/trusted-publishing) for
  `icudtl` on crates.io: repository `convex/icudtl`, workflow `release.yml`.

## Releasing

After the version bump is on the branch (for tzdata updates, the update PR
bumps it), tag that commit with the crate version and push the tag:

```sh
git tag v0.77.1
git push origin v0.77.1
```

`release.yml` runs CI, checks that the tag matches `Cargo.toml`, publishes to
crates.io, and creates the GitHub release.

crates.io only lets you add a trusted publisher to a crate that exists, so the
first version is published by hand with `cargo publish` and a personal token.
